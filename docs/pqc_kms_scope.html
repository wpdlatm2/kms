1. 한눈에 보기

암·복호화·서명서버가 대행하지 않는다. 암호 연산은 키를 받은 쪽(예: localhsm의 TPM 보호 키스토어)이 수행한다. 이 때문에 연산 용도가 없는 PQC·Edwards·KEM 키도 일반 키와 똑같이 생성·보관·회전·파기할 수 있다.

참고(이전 kms 저장소와의 관계) — 이전 wpdlatm2/kms(branch legacy)에는 KMIP 오퍼레이션 코드값(Encrypt·Decrypt·Sign·MAC)과 ARIA·SEED 블록암호 프리미티브는 있었지만, 이 오퍼레이션을 처리하는 서버 구현은 없었다. 따라서 "서버가 암복호화를 제공"한 적은 없고, 현재 pqc-kms도 키 관리 전용이다. 서버측 암복호화가 필요하면 별도 기능으로 추가해야 한다(9절).

3. 클라이언트 REST API

KMIP와 같은 수명주기를 제공하되 KMIP 데이터형을 쓰지 않고 보편값(소문자 상태, RFC 3339 시각, 표준 알고리즘명, hex 키값)을 쓴다. 요청은 최소한만, 응답은 가능한 많이 돌려준다.

5. 권한 모델

  • 모든 키는 서비스(권한그룹)에 필수 소속. 서비스를 묶는 상위그룹, 그룹과 무관하게 모든 키에 적용되는 ALL이 있다.
  • 클라이언트는 인증서 CN으로 식별되어 그룹에 권한 템플릿(owner = CRUD, guest = 읽기, 사용자 정의 가능)으로 매핑된다. 템플릿은 오퍼레이션(create·locate·getattributes·get·activate·revoke·rekey·setattribute·destroy)을 골라 만들고 수정한다.
  • 관리 권한(admin/audit)은 ALL·상위그룹·서비스 범위로 위임한다. audit은 읽기 전용이며 관리 API에서도 키 값은 나오지 않는다.
  • 모든 권한 부여·변경에 승인번호와 담당자가 필수이다.

6-1. 대시보드·서비스 제어

  • 대시보드: 키 서버 가동·보호 방식·키 상태 분포, KMIP/REST/관리 API 포트 응답과 서버 인증서 만료일, 감사로그 해시 체인 무결성(client·admin·console), 컨테이너 상태(실행·healthy·재시작 횟수), 호스트 디스크·메모리·부하, 24시간 로그인 성공/실패/잠금 계정. 종합 판정 정상/주의/위험과 사유 목록, 15초 자동 갱신.
  • 시작·중지·재기동: 전체 관리자(admin)만. 승인번호·담당자·서비스 이름 입력 확인 필수, 요청과 결과가 감사 기록에 남는다. 콘솔은 Docker 권한이 없고 호스트 에이전트(kmsagent, systemd, Unix 소켓)가 고정 목록(kms·console)의 start/stop/restart만 수행한다. 감사 권한자는 조회만 가능.

6-3. 시스템 로그와 자가점검

  • 기동·종료·오류·서비스 제어·감사로그 무결성 점검·관리 이벤트를 호스트 시스템 로그(syslog/journald)에 기록(journalctl -t kmsd -t kmsadmin -t kmsagent). 감사 파일과 별개이며 docker logs에도 유지.
  • 자가점검(기본 5분): 권한 없는 전용 인증서로 KMIP(버전 협상·Query·Locate)·클라이언트 REST·관리 API·마스터 키(TPM 봉인/해제 왕복)·저장소·데이터 폴더 쓰기를 점검해 한 줄로 기록. 실패 ERR, 복구 NOTICE, 실패·복구는 감사 기록과 대시보드에도 반영.

6-2. 계정·보안 설정

  • 비밀번호 규칙(설정 가능): 최소 길이 8–64, 문자 종류 1–4종, 계정 이름 포함 금지, 같은 문자 3회 연속 금지, 이전 비밀번호 재사용 금지(0–10회), 유효 기간(0–365일)과 만료 예고, 관리자가 설정한 비밀번호는 첫 로그인에서 변경.
  • 로그인 실패 잠금(설정 가능): 실패 횟수 3–10, 집계 시간 1–60분, 잠금 시간 0–1440분(0 = 관리자가 풀 때까지). 사용자 존재 여부를 노출하지 않는 동일한 응답.
  • 세션: 최대 1–24시간, 미사용 5–240분. 비밀번호 변경·재설정 시 해당 사용자의 다른 세션 종료.
  • 계정 관리: 추가·비밀번호 재설정·잠금 해제·OTP 초기화(승인번호·담당자 필수), 변경 전·후 설정값 감사 기록. 로그인 성공/실패·잠금 등 인증 이벤트는 사유·IP·브라우저·세션 식별자와 함께 기록(비밀번호 제외).

6. 웹 관리 콘솔

키(필터·검색·생성·상세·수명주기 동작) · 서비스·그룹 트리 · 권한 템플릿 편집 · 클라이언트 매핑 · 관리자 위임 · 감사·로그 · 라이프사이클 도움말. 로그인은 비밀번호 + OTP(TOTP, RFC 6238)이며 Android·iOS 무료 인증 앱을 쓴다. 복구 코드 10개(1회용). 세션·CSRF·실패 횟수 제한 적용.

7. 감사·증적 (금융감독규정 · ISMS-P)

  • 클라이언트 / 관리 API / 콘솔 로그를 분리하여 기록. 항목에 순번·분류·결과·요청ID·승인번호·담당자 포함.
  • SHA-256 해시 체인 + HMAC(TPM 봉인 키)로 변조·삭제·삽입 탐지, 일 단위 파일, 보관기간 하한(기본 5년), 무결성 검증, 증적 ZIP 내보내기(매니페스트), 정기 검토 기록, syslog(TLS) 외부 전송.
  • 로그인 실패·TLS 인증서 실패·권한 거부·키 값 반출·감사로그 조회까지 기록. 상세와 한계는 docs/AUDIT_COMPLIANCE.md.

8. 검증 현황

  • 단위·통합 테스트(권한 모델, 암호화 저장소, KMIP 전 버전, REST, 콘솔·OTP RFC 벡터, 감사 체인 변조 탐지), 퍼징·race(Linux Docker), 독립 구현체 PyKMIP로 KMIP 1.0/1.2/1.4 확인.
  • 111 서버(TPM)에서 localhsm 연계 통합테스트 0 failure: 매핑 → KMIP 조회·동기화 → 회전(무중단) → 침해·비활성 → 템플릿 수정 → REST → 감사 증적.
  • GS 인증 관점 입력값 검증·안정성 점검 결과는 docs/GS_TEST_REPORT.md (자체 점검이며 인증 결과가 아님).
